What this establishes

Non-modal, opened on demand from a quiet header pip. Nothing here stole focus to appear.

Each run reads at a glance — state as color and shape, not just text — with detail one expand away.

Decisions live inline: approve/reject an irreversible action right where it surfaces. No modal, no toast storm.

The one animated element on the page is the live pulse — the calm signal that something is running.

The problem

Autonomous work is easy to run and hard to watch calmly

Once Plane can spin off agents — triaging, summarizing, tidying sprints — the risk isn't the work, it's the attention tax of the work. The naïve build sprays toasts on every step, throws a modal for every decision, and leaves the user babysitting a log. The research is blunt about this: over-notifying (“cry-wolf”) is treated as worse than having no status system at all.

So the design goal is inverted from “show everything” to “stay quiet, earn every interruption.” The user should be able to walk away and trust they'll be pulled back only when a decision genuinely needs them.

Guiding budget. Current guidance caps unsolicited agent notifications at roughly 3–5 per user per day, across all agents combined — an architectural constraint, not a preference. Everything else routes to a quiet inbox or stays ambient.

Principle · match signal loudness to stakes

Four layers, and only one of them interrupts

The prevailing model for ambient agents is a tiered status system. Loud tiers are a scarce, budgeted resource; ambient tiers are the default. An interrupt is for a decision, never for a status update.

Open decision · where the surface lives

Three surfaces — a recommendation, not a verdict

This is the first thing we need your call on. Each maps cleanly onto patterns Plane already ships. Across the field, low-concurrency products use a serial list and high-concurrency ones graduate to a fleet board — so v1 is a simple list that can grow a board later without reshaping the data.

Option A

Dedicated side panel

A persistent, collapsed-by-default drawer listing active + past runs.

  • Best home for a live master–detail view
  • New global chrome to introduce
strong “home base”, weak at reach
Option B

Inbox-style hub

Agents become a filterable category in the existing notifications inbox.

  • Reuses shipped notification patterns
  • Inbox is built for after-the-fact, not live
cheap to build, weaker in-flight
Recommended

Hybrid: panel + inline

Global panel as home base, plus a compact indicator on the entity an agent is acting on.

  • Live view and contextual reach
  • Completions still land in the quiet inbox
  • Largest surface area to build
best coverage of “in-flight + after”

The contract · @plane/agents scaffolded ✓

One run, a small state machine, two message streams

We've stubbed a provisional, transport-agnostic contract as an isolated workspace package — the seam the (separately built) agent runtime adheres to, and which tests mock freely. Every leading product converges on the same shape: a master–detail list of runs, state shown as named status + steps (never a percent bar), with the blocking state pinned above all others. The lifecycle:

queued→ running⇄ waiting_for_input/ awaiting_approval→ succeeded· failed· cancelled

retryre-run, optionally from checkpoint

events per run carry a monotonic sequence → gap-detection + reconcile after reconnect.

Principle · the settled vocabulary of steering

Interrupt and steer are different actions

The #1 documented failure across Cursor, Claude Code, and Codex is conflating the two. We split them deliberately, and gate only the irreversible.

Stop

Interrupt

Hard stop. Ends the run, keeps completed work, drops the in-flight step. A terminal cancel.

⏎ steer

Correct

Inject guidance without killing the run. Applied at the next tool boundary — the agent keeps going, redirected.

Approve inline

Only boundary-crossing actions (destructive, irreversible) pause and ask — right in the run row, never a modal.

Complete → review

Done is a quiet badge plus a reviewable artifact (“Review changes”), not a popup. Failures offer retry.

How it plugs into Plane

Compartmentalized, riding seams that already exist

@plane/agents ✓ Isolated package — contracts, IAgentService / IAgentEventTransport, and a pure event→state reducer (no React/DOM). The reusable brain both web and a future native client wrap in their own store. Typechecks clean.
durable state Client holds no authoritative state — a projection rebuildable from listRuns + the event stream. Refresh, reboot, app-close → just re-hydrate a snapshot and resume by sequence.
transport A seam, not a decision yet: SSE · WebSocket via apps/live · SWR polling. Research favors milestone events, not token streams, for background work.
apps/web Wired via the existing @/plane-web CE/EE alias — the override seam Plane already uses to add features without touching core.
apps/api Persist run config on the existing Integration tables; emit outbound state via webhooks. New bgtasks module only if we own orchestration.
Deferred on purpose. Store wiring, UI components, and any backend app are not scaffolded yet — they depend on the surface and transport calls below. We built only what's unambiguous.

Locked for v1

Four decisions — scope deliberately small

✓

Surface — hybrid

Global panel as home base + one inline indicator on work items. Thin first cut; a fleet board composes on later.

✓

Transport — reuse apps/live

Backend publishes run events → Redis → the existing live service relays them. A plain event channel, not Yjs — bending a CRDT doc into an event bus was the friction to avoid. List/history/commands over REST.

✓

Scope — work items only

v1 observes runs targeting work items. Cycles / pages / workspace-level land in the backlog.

✓

Orchestration — backend owns it

The pre-supposed backend owns run lifecycle. We observe over the contract and send commands. No new bgtasks or Django app from us.

Deferred to backlog — push notifications + budget logic, fleet board, non-work-item targets, plan-approval-before-run, checkpoints/rollback, best-of-N. Each composes on top of v1 without reshaping the data.
