Architecture · top-down · agent visibility + agentic demo

One pure contract, two wrappers, a live LLM on stage

A framework-free core (@plane/agents) defines the seam — run/event/command types plus a total, idempotent reducer. Two layers wrap the same functions: a private LLM runtime + Plane client + HTTP bridge (@plane/agents-demo), and a flag-gated web surface (apps/web/ce) — MobX store, WebSocket transport, hooks, panel UI. The core has zero framework deps; both wrappers only add I/O, lifecycle, and pixels.

@plane/agents — pure contract + reducer (the seam) @plane/agents-demo — LLM runtime + Plane client + bridge apps/web/ce — store · transport · hooks · UI human-in-the-loop approval gate

01 · The spine

Three layers, one center of gravity

The pure core sits in the middle. It depends on nothing. The demo runtime wraps it to produce events; the web layer wraps it to project them into UI. Neither wrapper edits the core, and the core never imports React, MobX, Node, or the DOM.

02 · Data flow

Two directions around the reducer

Events flow one way (runtime → panel) and commands flow the reverse (panel → runtime) — but a command never optimistically mutates the UI. It resolves a parked promise on the bridge, which emits a new event back through the observe lane. One source of truth, always.

Observe

Live & snapshot — a run changes, the panel reflects it

runtime → panel

The Tool Runner drives tools; each tool call maps to a step and emits a sequence-stamped TAgentEvent. The bridge folds events into an in-memory reduced state and serves it over HTTP. The panel polls listRuns for the authoritative snapshot (reconcile); the WebSocket transport carries live events (applyEvent) — same reducer, two entry points.

03 · UI composition

Component tree — flag before hooks, lazy, error-isolated

Mounted once in the workspace header. AgentsRoot evaluates the flag before any hook that could open a socket or poll (flag-off returns null, zero network). The panel bundle is React.lazy — not fetched until the flag is on and the drawer opens. The whole surface sits under an error boundary that degrades to "Agents unavailable" instead of white-screening the host.

05 · Key concepts

Five things to hold in your head

The contract is the seam

@plane/agents owns the types, the two interfaces, and the reducer. Change the contract and every layer moves together; change a wrapper and nothing else notices.

The client is a projection

Local state is never authoritative — it is fully rebuildable from listRuns + the event stream. Refresh, reboot, reconnect all reduce to the normal load path via reconcile.

Flag-gated, no core edits

Everything enters through @/plane-web and mounts at one header seam. VITE_ENABLE_AGENTS is checked before any socket or poll — flag-off is byte-for-byte today, zero network.

Human-in-the-loop gate

bulk_close can't mutate until a human taps Approve. The gate lives inside the tool's run function — the panel's approval UX is literally the LLM's safety rail.

The runtime is a real LLM

Anthropic Tool Runner on claude-opus-4-8 drives plan → call → loop. The SDK owns the loop; the code owns only the tool functions and the rails prompt.
