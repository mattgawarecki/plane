Conventions for a new package

Naming: @plane/&lt;name&gt;, version matching monorepo, private: true, license: AGPL-3.0.

Template (from /Users/mattgawarecki/projects/plane/packages/logger/package.json + tsconfig.json): - "type": "module", built with tsdown (tsdown.config.ts); main/module/types → ./dist/..., plus an exports map. - Standard scripts: build (tsdown), dev (tsdown --watch), check:lint (oxlint), check:types (tsc --noEmit), check:format/fix:* (oxfmt), clean. - tsconfig.json extends a shared preset: @plane/typescript-config/{node-library,react-library,base,nextjs,react-router}.json (/Users/mattgawarecki/projects/plane/packages/typescript-config/), with paths: { "@/*": ["./src/*"] }. - devDeps reference shared config via "@plane/typescript-config": "workspace:*" and pinned deps via catalog:. - Source lives in src/, plus a README.md.

Dependency wiring

Packages depend on each other and apps depend on packages via workspace:* protocol (pnpm resolves locally). E.g. apps/web imports @plane/{types,constants,utils,hooks,services,ui,propel,editor,i18n,shared-state,tailwind-config,typescript-config}; apps/live imports @plane/{decorators,editor,logger,types,typescript-config}. Foundational leaf packages: types, constants, typescript-config.

Best place to add compartmentalized feature code

Create a new packages/&lt;feature&gt; package named @plane/&lt;feature&gt;. This is the clean, isolated seam: 1. Copy the shape of packages/logger (Node) or a react-library package (for UI/React) — package.json + tsdown.config.ts + tsconfig.json extending the right @plane/typescript-config preset + src/. 2. Consume it from an app (e.g. apps/web) by adding "@plane/&lt;feature&gt;": "workspace:*".
